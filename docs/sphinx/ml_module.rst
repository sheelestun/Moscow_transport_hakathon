ML-модуль
=========

Модуль ``ml/src/`` — признаки, обучение CatBoost-ансамбля и инференс-сервис на FastAPI. Подробности и команды —
``ml/README.md``; замеры скорости и надёжности — ``ml/PERFORMANCE.md``; эмулятор NDTP — ``ml/EMULATOR.md``;
статистика датасета — ``ml/DATASET_STATS.md``.

Задача
------

Прогнозная точка — пара (ТС, момент T). Нужно предсказать задержку в секундах (факт − план) на первой остановке
ТС, плановое прибытие на которую попадает в окно (T+10 мин, T+15 мин]. Метрика — MAE.

- Модель учит **поправку к подсказке**: цель ``target_delay_s − cur_dev_s``, прогноз
  ``delay = cur_dev_s + поправка``.
- Признаки — только данные, доступные на момент T: телеметрия с ``event_time <= T``, **плановое** расписание и
  подсказка. Фактические времена прибытия из расписания не читаются (в ``train/schedule.csv`` лежат факты и по
  целевым остановкам validate — это утечка из будущего, мы её не используем).

Данные
------

- **train** — телеметрия + расписание с фактами + разметка ``labels_train.csv`` (13 реальных ТС и 26 синтетических
  клонов, которые организаторы добавили «для объёма»).
- **test** — то же для 13 реальных ТС, разметка ``labels_test.csv`` (с ответами — для самопроверки).
- **validate** — 151 точка **без ответов**; прогнозы по ним — ``submission.csv``, скор считает платформа.
- Всё — один день, 2026-01-06. ``validate/traffic.csv`` побайтно совпадает с ``test/traffic.csv``.

Признаки (56, :mod:`features.tabular`)
--------------------------------------

- **рейсы и конечные**: разрыв плана > 5 мин = конечная. Внутри рейса задержка соседних остановок коррелирует на
  0.96, через конечную — на 0.02; признаки ``n_trip_breaks``, ``tgt_idx_in_trip``, ``tgt_left_in_trip`` ... — самая
  сильная группа;
- **история по GPS**: прибытия на пройденные остановки восстановлены из GPS (ближайшая точка к остановке, после
  которой ТС отъехало; медианная ошибка ~3 с) — ``gps_last_dev``, ``gps_med3``, ``gps_slope``, ``overdue_s`` ...;
- **движение**: ``spd1/5/15``, доля стоянки ``stop5/15``, ``moving_spd15``;
- **положение и ETA**: ``dist_tgt_m``, ``route_left_m``, ``eta_dev_s``, ``req_speed_kmh``;
- **ручные отметки факта** (``manual_fill``, ~18% остановок, задержка там ≈ 0);
- **маршрут** (категориальный ``route``) и **время суток**.

Модели
------

- **Основная**: 5 моделей CatBoost (глубина 8, 600 итераций, RMSE на поправку) с разными seed, прогноз — среднее.
- **Неопределённость**: MultiQuantile-модель (интервал 10–90%, конформно откалиброван до 80% покрытия) и
  MultiClass-классификатор early / ontime / late (``risk_score`` = P(опоздание > +120 с), AUC ≈ 0.97).
- **GPS-режим для живого потока** (``train_catboost.py --gps``). Официальная ``cur_dev_s`` = (факт − план) на
  последней остановке с **планом** <= T, и у ~45% точек этот факт наступает уже после T. Backend на потоке считает
  подсказку честно — задержка на последнем прибытии, найденном по GPS. Для него обучен отдельный комплект моделей
  на такой подсказке; сервис выбирает его по ``cur_dev_mode`` / ``ML_DEFAULT_CUR_DEV_MODE``.
- Причины прогноза — SHAP-вклады признаков CatBoost, сгруппированные в понятные коды (:mod:`explain`).

Валидация
---------

- **holdout**: обучение на train → проверка на test (прокси скора платформы);
- **proxy K-fold**: 5 фолдов блоками по 30 мин по реальным точкам, клоны остаются в обучении — так устроен validate;
- **LOVO**: ТС откладывается целиком вместе с клонами — честная оценка на новом ТС.

Результаты (MAE, с): holdout **39.8** (бейзлайн ``cur_dev_s`` 93.4), proxy **38.8** (88.4), LOVO **78.9** (88.4).
Оценка скора платформы ≈ 1.0. Актуальные цифры — ``GET /metrics/model`` сервиса.

Скорость
--------

В проде работает **нативный CatBoost**. Сервис: ~25 мс на точку внутри (признаки ~10 мс, 5 моделей ~3–5 мс,
причины ~35 мс при одиночном запросе), пачкой ~10–20 мс на точку; холодный старт контейнера ~2 с.

ONNX-экспорт (``export_onnx.py``) проверен и **не используется**: CatBoost не выгружает в ONNX категориальные
признаки, поэтому ONNX-модель пришлось учить без ``route`` (MAE ~48 против ~40), SHAP-причины в ONNX недоступны,
файлы больше (58.7 МБ против 12.4 МБ), а INT8-квантизация не работает с деревьями CatBoost. Сама модель — ~10%
времени ответа, выигрыш от ONNX (~3 мс) несущественен при требовании < 1–2 с.
