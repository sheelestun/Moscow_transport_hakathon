Inference API
=============

HTTP-сервис инференса — :mod:`inference_service` (FastAPI, порт 8001). Swagger UI — ``http://localhost:8001/docs``
при поднятом сервисе. На сервере ML наружу не опубликован: его вызывает только backend (``http://ml:8001``).

Эндпоинты
---------

``POST /predict`` и ``POST /predict/batch``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Прогноз задержки ТС на целевой остановке. Клиент шлёт **сырой контекст**, признаки считает сервис той же
функцией, что при обучении (онлайн-прогноз совпадает с ``submission.csv``):

- ``sample_id``, ``tr_id``, ``T``, ``target_stop_id``, ``target_time_begin``, ``cur_dev_s``;
- ``telemetry`` — пакеты NDTP ТС за последний час+ (пакеты позже ``T`` сервис отбрасывает сам);
- ``schedule`` — плановое расписание ТС;
- ``cur_dev_mode`` (необязательно) — ``official`` (подсказка как в датасете, для сабмита) или ``gps`` (подсказка
  по последнему GPS-прибытию, как считает backend на потоке); по умолчанию — ``ML_DEFAULT_CUR_DEV_MODE``.

Пачка: ``{"requests": [...]}`` → ``{"responses": [...]}``.

Ответ (главное):

- ``delay_pred_sec`` — прогноз задержки, с; ``delay_interval_sec`` — интервал, куда факт попадает в ~80% случаев;
- ``p_early`` / ``p_ontime`` / ``p_late``, ``risk_score`` (= ``p_late``), ``risk_level`` (green / yellow / red);
- ``reason_pattern``, ``recommendation`` (коды для дашборда), ``causes`` и ``recommendation_text`` (текст),
  ``top_features`` (вклад признаков, SHAP);
- ``lead_min`` и ``horizon_ok`` — целевая остановка в окне (T+10, T+15] мин;
- ``data_status`` — ``live`` / ``stale`` / ``off_route`` / ``no_telemetry`` / ``fallback``;
  ``critical_trip`` — открывающий / закрывающий рейс; ``catchup_speed_kmh`` — скорость, чтобы вернуться в график.

Скорость: ~25 мс на точку внутри сервиса, пачкой ~10–20 мс на точку (нативный CatBoost).

``POST /whatif/predict``
~~~~~~~~~~~~~~~~~~~~~~~~

Оценка сценария (``add_reserve``, ``adjust_interval``, ``detour``, ``signal_priority``, ``hold_at_stop``):
эвристический сдвиг задержки, риск пересчитывается по интервалу модели.

``GET /health``, ``GET /metrics/model``, ``GET /model/info``, ``POST /reload``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Статус и загруженные комплекты моделей; метрики валидации, живая latency p50/p95, покрытие интервала; описание
моделей; горячая перезагрузка моделей из ``ML_ARTIFACTS`` без перезапуска контейнера.

Надёжность
----------

- Ошибка модели или признаков → ответ 200 с ``data_status: fallback`` и прогнозом = ``cur_dev_s`` (сервис не падает).
- Одна плохая точка в пачке не валит пачку: пересчёт поштучно.
- 422 — только если у ТС нет планового расписания (прогнозировать не к чему).
